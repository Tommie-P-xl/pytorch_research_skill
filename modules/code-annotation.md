# 代码学习与注释

这是共享模块：既可被项目构建流程最后调用，也可通过主入口独立用于学习他人代码。
**独立学习时不要求读取其余五个模块。**

## 1. 确认注释契约

从用户要求中识别模式与已有答案，仅询问缺失信息：

- 模式：在对话中讲解 / 原文件加注释 / 指定学习副本。讲解不默认编辑文件；加注释默认原位，用户要求副本时尊重目标。
- 范围：指定文件、类/函数、调用链或全项目。全项目先列实际文件并分批处理，不只注释入口就声称完成全部。
- 程度：简洁、标准、教学，定义见下表；已明确“详细学习注释”按教学理解，不重复询问同义表达。
- 语言：默认中文 docstring/解释，保留英文标识符及常见术语；用户指定语言优先。

用户只说“加注释”而未明确程度时询问档位；没有答案则先追踪代码与范围，不替用户选定档位或开始依赖该选择的注释写入。
用户要求“采用推荐程度”时可选标准并说明。

| 程度 | 覆盖范围 | 内容与密度 |
|---|---|---|
| 简洁 | 关键接口、易误读分支、重要维度变化 | 用途、关键约束、必要 Shape；不逐行复述 |
| 标准 | 重要文件说明、核心类/函数 docstring、forward 等关键步骤 | 参数/返回值、pipeline 位置、设计原因、关键 Shape |
| 教学 | 标准范围 + 关键算法步骤和跨模块数据流 | 符号含义、分步运算、reshape/permute/detach 原因、梯度/训练语义、与调用方的关系；不机械解释每行语法 |

## 2. 先理解，再注释

1. 阅读目标代码及必要调用方/被调用方、配置、batch 定义；有 CodeGraph 时优先用其结构查询获得调用关系，否则使用当前可用工具。
2. 追踪输入 → 中间张量 → 输出，区分事实、配置条件和推断。
3. 只对可确定的维度标 Shape；动态维度用符号及条件。配置未知时注明依赖，不猜常数。
4. 对论文映射仅写来源已确认的含义；不把经验推断写成作者意图。
5. 发现 bug 时先说明位置与证据，将修复作为独立事项；本注释任务不顺便改算法。

## 3. 注释规则

- 英文变量/函数/类名不改；默认中文解释，可保留 Attention、logits、token 等术语。
- 重要文件说明功能、输入/输出与 pipeline 位置；已有正确说明保留，避免重复。
- 核心类/函数 docstring 说明用途、必要参数、返回值、约束与设计；不要把现有英文技术文档整段删除。
- 解释“为什么”和算法阶段，避免 `# x 加 1` 这类语法复述。
- 在 forward、reshape/view、permute/transpose、flatten、pooling、Q/K/V、拼接、融合、特征接口等位置标关键 Shape。
- 常用符号：B=batch，C=channel，H/W=空间，N=token，D=embedding，K=类别。Attention 用 A 表示 head 数、Dh 表示单 head 维度，避免与图像 H 混淆。
- 标出 softmax 轴、归一化对象、广播或缩放意义；detach/no_grad 解释其实际梯度边界。
- 注释需与分支和配置一致，不因为名称带 attention 就套用标准算法。
- 不改变函数签名、默认值、返回结构、运算顺序、API、配置、路径和实验协议。不新增运行时打印/assert、类型注解或重命名。
- 保留 shebang、编码声明、许可证、未来导入位置及现有 tooling pragmas（type: ignore、noqa 等）。补模块 docstring 时放在合适位置，不破坏 future import 规则。
- docstring 可被程序读取；对反射/注册等敏感代码先检查调用关系，必要时仅用普通注释。

## 4. 教学注释示例

仅示范可直接嵌入既有 forward 的函数体；q/k/v 等应由原代码生成。
不要求把别人代码改成此实现。
`A` 是 head 数，`Dh` 是每个 head 的维度。
`q/k/v: (B, A, N, Dh)`，下面假设 self-attention 的序列长度相同。
`softmax` 结果是每个 query 对所有 key 的权重。

```python
# 最后两维相乘得到 query-key 相似度，缩放缓和维度增大时的数值幅度。
scores = (q @ k.transpose(-2, -1)) * scale
# (B, A, N, Dh) @ (B, A, Dh, N) -> (B, A, N, N)

# 最后一维是 key 位置；每个 query 的权重沿该维归一化。
weights = scores.softmax(dim=-1)
context = weights @ v
# (B, A, N, N) @ (B, A, N, Dh) -> (B, A, N, Dh)

# 先让 token 维回到 head 维之前，再将各 head 的特征并到 embedding。
context = context.transpose(1, 2).reshape(batch_size, num_tokens, embed_dim)
# (B, A, N, Dh) -> (B, N, A, Dh) -> (B, N, D)，其中 D = A * Dh
```

标准程度保留主要接口说明及关键维度变换，教学程度再展开算法因果；简洁程度只保留容易误读的说明。
这三个档位是不同密度，不是分别维护三套注释规范。

## 5. 核验与交付

- 对比 diff，检查仅修改注释/docstring，无计算、导入、API 或配置变化。
- 对注释前后做语法/AST 比较时忽略**真正的**模块/类/函数开头 docstring；其他字符串常量可能参与计算，不能一并忽略。
- syntax/AST 一致只支持结构未变，不替代对 docstring 反射和 pragma 的检查。
- 使用已有相关检查；仅注释不强制启动完整训练。依赖缺失时可先语法核验，说明未执行运行验证。
- 逐处核对 Shape 与运算、轴和配置；无法确认的内容明确标条件或待核实。
- 交付已处理文件、档位、覆盖范围、主要数据流、仍需确认的部分及验证结果。
- 用户只要求注释时不额外交付新架构、图表或大篇教程；独立学习路线到此结束。构建路线回主入口完成交付。
