# 代码学习与注释

用于理解、注释已有项目，或在新项目实现完成后补充学习说明。独立学习任务只执行本模块，不要求用户选择项目构建的其他模块。

**教学档的目标是把一段能直接讲给初学者听的解释写进源码。** 读者不能只看见“这是检测头”“这里做注意力”“形状变成某某”，还必须能理解术语是什么、这一步在解决什么问题、每个操作怎样改变数据，以及输出交给谁。全部教学内容应进入用户指定的源码或学习副本；聊天里的长解释、额外导览不能替代源码中的解释。

## 1. 确定范围、读者基础和编辑方式

从当前请求与对话中确定下列选项；已有答案不重复问。

| 选项 | 处理规则 |
|---|---|
| 是否修改文件 | “解释代码”在对话中讲解；“加注释”编辑指定源码；“写副本”只写到指定副本 |
| 范围 | 单个定义、某文件、调用流程或全项目；全项目不能自行缩成几个核心文件 |
| 程度 | 简洁、标准、教学；“初学者”“最详细”“像老师逐行讲解”按教学档处理 |
| 读者基础 | 根据用户已说明的背景调整；熟悉分类训练不代表熟悉检测、Attention、扩散或其他新算法 |
| 语言 | 默认中文，保留英文标识符；首次解释陌生术语，不用新术语解释另一个未知术语 |
| 编辑方式 | `patch` 或 `rewrite`；未指定时简洁选 patch，标准/教学选逐文件 rewrite |
| 注释保留策略 | 默认保留准确的已有说明并补足；用户允许替换时，可重写普通注释和删除失效的注释代码，保留许可证/编码/工具指令 |

用户仅说“加注释”且程度没有上下文依据时，再集中询问程度；等待时可先读代码。用户已经认可一份具体注释或要求“按刚才那样”，该样例就是教学密度基准，不能退回较短的概括式说明。

用户选择教学但未说明背景时，默认读者会基础 Python、了解 Tensor/卷积/分类训练，但**没有学过当前算法的代码逻辑**。不要求他先掌握算法术语才能阅读注释。用户明确要求更低或更高起点时，以用户为准。

| 程度 | 内容与密度 |
|---|---|
| 简洁 | 用途一句话，标出关键限制与容易看错的形状 |
| 标准 | 接口用途、输入输出、主要步骤、关键形状及原因 |
| 教学 | 基础概念与整体流程，加关键语句逐句解释、形状中间过程、广播/索引实例、算法原因、状态和梯度边界；密度参照第 4 节教学样例 |

**不要用“不要逐行复述基础语法”作为缩短教学注释的理由。** 不必解释每一个 `for` 的 Python 定义，但算法相关的赋值、循环、分支、解包、索引和 reshape 都要解释其具体语义。例如 `na = len(anchors[0]) // 2` 应解释列表为何两两配宽高、结果代表什么，而不只说“求 anchor 数”。

## 2. 先读完整实现，再写说明

1. 阅读目标文件的全部当前内容，列出模块级执行、每个类、构造函数、方法、函数与嵌套定义。查看必要调用方、配置和输入协议；构造函数与包装函数也不能略过。
2. 有 CodeGraph 时先用其结构/调用链工具；已返回的当前未过期源码视为已读，只补读缺口。没有此工具时用本地搜索和读取。不要把截断结果当作完整文件。
3. 对照实际计算追踪输入、输出和中间状态。确认列表/tuple/tensor、每个轴、坐标单位、默认配置、训练/eval 分支与启用条件。
4. 区分论文描述、当前执行逻辑、静态推导与运行测量。定义了 Focal/Dice/NMS 等工具不等于实际调用；注释掉的分支不执行。
5. 发现错误或不匹配时，解释受影响条件和源码依据，保留可执行逻辑；修复须属于用户另行授权的范围。不可把存在缺陷的实现讲成预期正确算法。

### 2.1 全项目任务建立逐文件清单

从实际目录列出入口、模型、数据、训练、评估、工具和测试。第三方依赖、环境、生成文件默认排除并列明原因；用户明确纳入时遵从。不能仅因目录名像工具或已有一句注释就略过。

记录范围、档位、读者起点、编辑方式以及各文件的定义清单、已处理算法、验证结果和未完成项。沿用现有计划即可，不强制新建任务文档。例如：

```text
范围：项目自有 Python；教学；读者会分类训练但不懂检测；rewrite
models/head.py    处理中   anchor定义、构造参数、各尺度forward、坐标解码
utils/loss.py     待处理   标签匹配、损失输入、detach与训练调用
train.py          已复核   取样至更新/验证/保存；AST一致；未实际运行训练
```

逐文件或按完整类/函数分段推进，保留进度；压缩上下文后接续，不自行降档。不用并行批量重写或模板生成替代逐文件阅读与复核。

## 3. 教学注释的具体写法与完成条件

### 3.1 文件、接口、关键语句三层都要有

**文件顶部建立读者所需的基础。** 说明当前文件处于数据/模型/损失/训练/推理哪一步，以及推荐阅读顺序。对理解文件必需的陌生概念给出“含义 + 小例子 + 在本实现中的用途”。例如 anchor 是参考宽高，grid 是位置网格，stride 是坐标换算倍率；这些不是已经找到的目标框。不要加入与本文件无关的整套算法教材。

**每个定义说明它与上下游的关系。** 构造函数讲参数的业务含义、由配置怎样传入、创建的层或状态为何需要；forward 讲输入格式、输出层级与状态分支；小包装讲它连接谁、是否有文件/设备/状态副作用。不把“建立持久状态”“字段供后续方法读取”“输入见签名”当成教学解释。

**把详细解释放到关键语句紧邻位置。** 函数开头可先讲流程，但不能只放一整段长摘要而让函数体缺少说明。展开卷积输出、解包、坐标换算、筛选、循环状态、梯度、聚合和返回等语句；紧密相连的简单操作可合讲，重要操作不能藏在函数级摘要里。

一条教学解释通常需要回答：输入表示什么 → 操作怎样处理它 → 结果表示什么 → 为什么下一步需要这个结果。无需每行都写四个固定标签，也不要求每处重复同一概念。

### 3.2 陌生概念必须先解释

- 不假设读者知道 anchor、objectness、logits、token、Q/K/V、位置编码、EMA、NMS、标签匹配等当前算法术语。
- 先用熟悉概念搭桥。例如分类输出 `(B,K)`，检测在空间位置输出框参数/目标分数/类别分数；Attention 的 value 是被加权汇总的内容，query/key 用于确定汇总权重。
- 说明“是什么”和“不是哪种容易混淆的数据”。例如 anchor 是参考尺寸而非检测结果；候选数不是目标数；某个 `bs` 在切片后代表块数。
- 区分术语与变量名。同名 `no` 在不同作用域可能分别是单 anchor 的输出数和整位置通道数；`N` 可以表示 token 或切片，必须在当前文件明确约定。
- 默认参数与实际传入值分开讲，不能把签名里的 COCO 80 类套到实际 10 类配置。

### 3.3 张量、索引与公式必须展开中间过程

不要只写最终 Shape。实际出现时按下列要求解释：

| 操作 | 教学解释必须包含 |
|---|---|
| `view/reshape` | 哪些轴拆分/合并、各轴意义、元素数为何保持；`-1` 推断的是哪个量 |
| `permute/transpose` | 操作前后轴顺序；为何下一步需要这个顺序；适用时解释连续内存布局 |
| 广播 | 两边 shape、长度为 1 的轴怎样扩展、哪些样本/位置共享什么值 |
| `cat/stack` | 沿哪个轴，前者扩已有轴、后者加新轴；为什么形状要兼容 |
| 高级/布尔索引、`nonzero` | 索引各列指什么、索引后 shape、位置数与目标数的区别 |
| `sigmoid/softmax` | 哪些值成为分数、哪些仍需解码；softmax 沿哪个语义轴，哪些权重和为 1 |
| 池化、阈值、局部峰 | 保留/丢掉什么空间信息、输出分辨率、选择条件；不只翻译函数名 |
| `detach/no_grad/eval` | 哪一路停止录图/回传，哪些路径仍可训练；eval 切模块状态，不自动关闭梯度 |
| 损失、标签匹配 | 预测/标签格式、正负样本如何选、返回日志与用于 backward 的量区别 |
| 坐标或单位换算 | 换算前后单位、缩放/平移顺序；如归一化→整图格→块内格→输入像素→原图像素 |
| 返回/状态分支 | train/eval、tuple/list 各项与层级，空输入/无候选及真实启用条件 |

**关键的多步变换配纸面数值例子。** 例如 `45=3*(10+5)` 如何拆通道；`(N,2)+(1,h,w,2)` 是否能广播；一个块偏移如何加回一个预测中心。例子应写清配置、输入尺寸、训练或推理状态；不能把静态算例称为实测 forward。对简单转发工具无需硬造 tensor 例子。

公式需配自然语言：每项由什么变量提供、为什么加/乘/平方、结果是什么单位。只写 `xy=(2*sigmoid-.5+grid)*stride` 仍然不足。

### 3.4 不达标与达标的区别

```python
# 不达标：计算anchor数量。
na = len(anchors[0]) // 2
```

教学档应到下面的具体程度：

```python
# anchors每组按[w1,h1,w2,h2,...]保存参考框宽高，不是已经检测出的框。
# 例[6,8,10,22,19,15]表示宽高为(6,8)/(10,22)/(19,15)的三个参考形状。
# 两个数配成一个anchor，所以6//2=3；na是每个网格位置的参考形状数。
na = len(anchors[0]) // 2
```

以下方式也不能算教学完成：

- 只在类前写“用于检测/注意力”，方法中只有 shape 缩写。
- 只列参数名、赋值属性名、callee 名称或原始返回表达式，没说明数据语义和原因。
- 给所有构造函数套同一句“建立状态”，给所有 forward 套同一句“输入输出见类说明”。
- 用 AST 自动扫描后套通用注释，未逐项核对具体实现；结构检查不能生成算法理解。
- 聊天解释详尽，源码却只有缩略版；用户已要求写进代码时必须落实到文件中。
- 解释高级概念时引入更多未定义术语；或者每行机械复述 Python，反而跳过算法原因。

可以用脚本定位语句、写回和验证，但注释内容必须依据已读实现逐项编写/复核，不以“每个定义都插入了注释”替代教学质量。

### 3.5 编辑模式与行为保护

`patch` 是局部落实修改；`rewrite` 是依据当前源码按文件顺序形成完整注释版本，**不是重写算法**。两种工具方式都可以满足教学档；文件长就按完整定义分段，最终检查整个文件。不能因工具名是 apply_patch 就少注释，也不能因整文件写回就宣称足够详细。

只加注释时：

- 保持签名、默认值、导入、运算顺序、返回结构、路径、配置和实验安排；不添加 print/assert/类型提示/重命名或调试 hook。
- 保留编码声明、shebang、许可证、future import 的合法位置，以及 `noqa`、`type: ignore`、格式化等工具指令。
- 普通旧注释可按授权替换；用户允许删旧注释时，可移除被注释掉的失效代码，不能删实际执行的分支。
- 现有 docstring 是可读取字符串。检查 `__doc__` 的用途，保留准确技术说明；无法排除语义影响时优先用 `#`，不要把任意字符串都当注释删掉。

写回过程：记录当前源码（含未提交改动）与编码/换行 → 生成完整候选 → 检查 diff/compile/AST → 写回前确认源未被并发改动 → 写回后复核所有定义。并发修改时重新读取合并，不从 Git 旧版本覆盖用户改动。

候选和快照遵守用户指定输出范围；候选验证后清理或明确区分，避免被当成项目源码扫描。无关的报告/生成器不是必须交付物，不擅自扩展项目。

### 3.6 完成前的教学验收

按具体对象检查，不用行数或 diff 大小评分：

1. **概念**：读者只懂分类网络，能否在当前注释中找到理解这份算法必需的术语及小例子？
2. **覆盖**：每个定义、构造参数的关键语义、算法步骤、分支和返回协议是否解释？小工具/备用路径也列明。
3. **逐句**：核心函数体是否在实际语句旁展开关键操作，而非只有开头长摘要？
4. **推导**：shape 是否给出中间变化及轴意义？广播/索引/坐标是否有必要的具体例子？
5. **连接**：输出供哪个模块使用、训练标签/loss 如何联系、梯度和状态边界是否清楚？
6. **真实性**：条件是否来自实际调用；被注释实现和未实现分支是否区别；示例假设/未运行边界是否明示？
7. **行为**：代码结构、接口、工具指令及原有用户改动是否保留？

若用户提供已认可的教学样例，逐项与样例密度比较。样例讲了术语、每条关键语句、中间 shape 与数值例子，新注释就不能只讲模块用途和最终 shape。

只有纳入范围的定义和关键步骤全部完成、教学与行为两项复核通过，才标记注释完成。缺运行环境可以明确“注释及静态检查完成、运行未验证”，不要求为注释启动训练。无法从现有证据确认的实现条件写成边界，不编造；缺源码导致无法解释的部分保留未完成状态。全项目交付必须列清待处理与排除项。

## 4. 对照样例：同样的计算，三种密度

下面三个 `attention_context` 的可执行计算相同。示例是学习密度基准，不要求把真实 Attention 重构成这个函数。

输入已由上游投影并拆头，q/k/v 均 `(B,A,N,Dh)`，这里要求相同序列长度、Dh>0、设备/类型兼容。它省略了上游 QKV 投影、mask、dropout 和输出投影；真实代码存在这些步骤时也须解释。

### 4.1 简洁

```python
def attention_context(q, k, v):
    """合并各注意力头的输出，返回 (B, N, A * Dh)。"""
    batch_size, num_heads, num_tokens, head_dim = q.shape
    scale = head_dim ** -0.5
    scores = (q @ k.transpose(-2, -1)) * scale
    weights = scores.softmax(dim=-1)  # 沿key位置归一化。
    context = weights @ v
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )
```

### 4.2 标准

```python
def attention_context(q, k, v):
    """计算各token的注意力特征并合并多个头。

    q/k/v均为(B,A,N,Dh)，输出(B,N,D)，D=A*Dh。
    要求q/k/v序列等长，Dh>0，dtype/device兼容。
    """
    batch_size, num_heads, num_tokens, head_dim = q.shape
    scale = head_dim ** -0.5
    # query与key做点积，按每头特征维缩放。
    scores = (q @ k.transpose(-2, -1)) * scale  # (B,A,N,N)
    weights = scores.softmax(dim=-1)  # 每query对所有key的权重和为1。
    context = weights @ v  # 加权value，得到(B,A,N,Dh)。
    # 先让同一token的各头排在一起，再合并头与每头特征维。
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )  # (B,A,N,Dh)→(B,N,A,Dh)→(B,N,A*Dh)
```

### 4.3 教学：读者没有学过 Attention

```python
def attention_context(q, k, v):
    """让每个位置按相关程度，汇总其他位置的特征。

    token在这里就是序列中的一个位置及其特征；若上游把图像拆patch，
    一个token可代表一个patch，但本函数自身不切图。
    query(q)表示当前位置拿什么特征去询问，key(k)是被询问位置的匹配特征，
    value(v)是最后实际被加权汇总的内容。q/k决定权重，v提供内容。
    本函数接收的是已投影且已拆头的q/k/v，不在这里创建QKV线性层。

    多头将特征分成A组分别计算，再拼回；不是把batch分到A个头里。
    B=样本数，A=头数，N=位置数，Dh=每头特征维，D=A*Dh。
    输入都是(B,A,N,Dh)，序列等长、Dh>0、dtype/device兼容；输出(B,N,D)。
    纸面例：B=2,A=4,N=8,Dh=16，输出为(2,8,64)，不是(2,4,8,16)。
    """
    # 读四轴信息；这里N是token数，不是原图裁出的切片batch数。
    batch_size, num_heads, num_tokens, head_dim = q.shape

    # 点积要累加Dh项，维数增加时数值幅度可能增大。
    # Dh**-0.5=1/sqrt(Dh)，例如Dh=16时scale=.25；缩放后再softmax，
    # 缓和大分数导致权重过于集中的情况，不是改变输出特征维数。
    scale = head_dim ** -0.5

    # k原为(B,A,N,Dh)，最后两轴交换→(B,A,Dh,N)。
    # @是矩阵乘，(N,Dh)@(Dh,N)→(N,N)，B/A轴分别计算，不混合不同样本。
    # scores=(B,A,N_query,N_key)；scores[b,a,i,j]表示位置i与位置j的匹配分数。
    # 示例每个头8个位置，会有8×8分数表，还不是最终value特征。
    scores = (q @ k.transpose(-2, -1)) * scale

    # dim=-1是key位置轴：固定一个样本/头/query，对全部key做softmax。
    # 每行权重非负且和为1，而不是沿batch、head或query轴归一化。
    # 两个key分数若为[0,log(3)]，softmax为[.25,.75]，后一位置贡献更大。
    weights = scores.softmax(dim=-1)

    # weights=(B,A,N_query,N_key)，v=(B,A,N_key,Dh)。
    # 对key轴加权求和→(B,A,N_query,Dh)，每个query得到Dh维汇总特征。
    # 纸面单分量例：value为[2,10]、权重[.25,.75]，汇总=.25*2+.75*10=8。
    # 各Dh分量都这样求和；不是取最大key，也不是把所有位置直接压成一个向量。
    context = weights @ v

    # 当前(B,A,N,Dh)，先transpose(1,2)→(B,N,A,Dh)，
    # 使同一token的各头相邻，再reshape合并A/Dh→(B,N,A*Dh)。
    # 例(2,4,8,16)→(2,8,4,16)→(2,8,64)，直接略过换轴会弄乱token/头对应关系。
    # 换轴后内存可能不连续，reshape必要时复制；view要求布局兼容。
    # 未使用detach/no_grad，若输入需要梯度，梯度会沿匹配、权重及value运算回传。
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )
```

### 4.4 检测解码的教学样例：不只写 Shape 或公式

本例只展示密集检测头中的一个步骤，不是完整可运行检测器。假定具体模型已经提供 `logits`、局部 `grid`、块偏移、像素 anchor 和当前尺度 stride。相同要求适用于其他算法，不是要求所有项目都采用 anchor。

```python
# 推理态密集头示例：N=块数，A=每位置参考形状数，K=类别数。
# logits=(N,A,h,w,K+5)，末轴为[tx,ty,tw,th,obj,cls0,...]。
# anchor是参考宽高，不是已找到的目标；例如[6,8]代表宽6像素高8像素。
# grid=(1,1,h,w,2)保存块内[列x,行y]，patch_off_xy=(N,1,1,1,2)
# 保存每块在当前尺度整图中的左上角，两者都是网格单位。
# anch_wh=(1,A,1,1,2)是像素宽高；stride=8表示本尺度坐标乘8变输入像素。

# sigmoid把原始实数变到(0,1)。obj/cls成为分数，但前4项还不是像素框，
# 后面需加位置、乘尺度或乘anchor；各类独立sigmoid，分数不要求和为1。
y = logits.sigmoid()

# (1,1,h,w,2)+(N,1,1,1,2)→(N,1,h,w,2)，再沿A轴广播。
# 同一块所有位置加相同块起点，不同块加各自起点：块内格→整图格。
grid_off = grid + patch_off_xy

# ...保留前面N/A/h/w轴，最后轴0:2选中心参数。
# *2-.5允许中心在本格附近移动，加grid/块起点定位，乘stride转输入像素。
# P3纸面例：sigmoid中心=(.5,.5)，局部格=(5,7)，块起点=(24,48)，stride=8，
# 中心x=(.5*2-.5+5+24)*8=236，y=(.5*2-.5+7+48)*8=444。
# 这还不是撤销letterbox后的原图坐标，调用方需另外减pad、除resize比例。
y[..., 0:2] = (y[..., 0:2] * 2. - 0.5 + grid_off) * stride

# 宽高参数先变为正缩放系数，再广播乘对应像素anchor：
# (N,A,h,w,2)*(1,A,1,1,2)→(N,A,h,w,2)。
# sigmoid=.5时(2*.5)²=1，宽高等于参考形状；.75时为2.25倍。
# 用像素anchor，不要与训练中“已除stride的网格anchor”混用。
y[..., 2:4] = (y[..., 2:4] * 2) ** 2 * anch_wh

# 现在末轴是[xc像素,yc像素,w像素,h像素,obj分数,K类分数]，仍是候选。
# A=3、K=10时每位置3*15=45项；24×24图共3*24*24个候选，不等于目标数。
# 密集展开空间与anchor轴后，调用方再筛置信度并NMS去重；训练通常保留原logits给loss。
```

## 5. 验证与交付

教学验收和行为验证分开做，两项都需要。

- 比较前后 diff，确认只变普通注释/允许变更的 docstring，没有改导入、签名、运算、返回或配置。
- 用同一解释器 `compile` 检查语法，再比较 AST。纯 `#` 修改可比较完整 AST；改变 docstring 时只忽略真正的定义开头 docstring，不能过滤全部字符串。
- 若只改 `#`，还可比较忽略 COMMENT/NL 后的 token；许可证与工具注释另行核对，不因忽略 COMMENT 而略过保护。
- 依赖缺失时可静态验证，不为注释任务安装依赖、下载权重/数据或启动完整训练。说明未执行哪些检查；静态形状推导不是实际 forward 测量。
- 完整 AST 相同不证明注释准确：再对照真实配置、启用条件、每个轴/单位、返回层级和调用方核对教学内容。
- 交付说明读者起点、档位、模式、改了哪些文件、备份/副本位置、已完成/未完成/排除项与验证限制。不只报注释行数，也不把几处补丁称为全文件完成。

### AST 检查示例

下面只验证可执行结构，不验证教学密度。`before/after` 是用原编码读取的完整文本；去掉真正的 docstring 后，其他字符串如路径、报错消息、配置值仍需保持。

```python
import ast


class IgnoreDocstrings(ast.NodeTransformer):
    def strip_docstring(self, node):
        self.generic_visit(node)
        if ast.get_docstring(node, clean=False) is not None:
            node.body = node.body[1:]
        return node

    visit_Module = strip_docstring
    visit_ClassDef = strip_docstring
    visit_FunctionDef = strip_docstring
    visit_AsyncFunctionDef = strip_docstring


def executable_ast(source):
    compile(source, "<annotation-check>", "exec")
    tree = IgnoreDocstrings().visit(ast.parse(source))
    return ast.dump(tree, include_attributes=False)


if executable_ast(before) != executable_ast(after):
    raise ValueError("注释候选版本改变了代码结构，停止写回并检查差异。")
```
