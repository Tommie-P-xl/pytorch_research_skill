# 代码学习与注释

本模块既能用于给新项目加注释，也能单独用于读懂已有代码。**只学习代码时，不需要读其余五个模块。**

## 1. 先确定注释方式

从用户要求中找出下面几项，只问还不明确的部分；编辑方式未指定时按第 3 节选择，不额外要求用户回答：

| 要确认什么 | 例子与处理方式 |
|---|---|
| 是否修改文件 | “解释这个函数”只在对话中讲；“给它加注释”修改原文件；“做学习副本”写到指定副本 |
| 注释哪些代码 | 一个文件、一个函数、函数之间的调用过程，或整个项目。整个项目要先列出实际文件，再逐文件处理，不能自行缩成几个核心文件 |
| 讲多细 | 简洁、标准、教学。“最详细”“逐文件详细解释”“详细学习注释”按教学理解，不再询问同义选项 |
| 用什么语言 | 默认中文解释，保留英文变量名和 Attention、logits 等常用术语；用户指定其他语言时遵从 |
| 怎么编辑 | `patch`（局部补充）或 `rewrite`（生成完整注释版本）；用户指定时优先，否则按档位选默认方式 |

用户只说“加注释”时，先询问程度；没有答案可以先读代码，但不自行选择档位写入注释。用户说“采用推荐程度”时，可选择标准并说明。

| 程度 | 要写什么 | 适合什么情况 |
|---|---|---|
| 简洁 | 一句话说明用途，标关键限制和容易看错的形状变化 | 熟悉 PyTorch，只想快速看懂关键点 |
| 标准 | 说明输入、输出、主要步骤、这样写的原因和关键 Shape | 能读基本代码，需要理解模块怎样工作 |
| 教学 | 在标准基础上，展开算法步骤、符号、维度变化和梯度影响 | 初次接触该算法，希望跟着代码一步步学 |

三档采用同一套正确性要求，只改变解释的多少。不要为了“教学”逐行解释赋值、循环等基础语法。

### 全项目任务：先建立实际文件清单

“整个项目最详细注释”已经确定了范围和教学档，不再问是否只处理模型。先列出项目实际拥有的 Python 文件，包含入口、数据、模型、训练、评估、工具和测试等；第三方依赖、虚拟环境、生成文件默认排除并说明原因。用户明确纳入的文件优先，不能只凭目录名排除。

沿用项目现有记录方式，或在当前计划中保存清单，不强制新增任务文件。每个文件记录：状态、类/函数清单、重点步骤、验证结果和未解决问题。例如：

```text
范围：项目自有 Python 文件；档位：教学；编辑：rewrite
models/attention.py   待处理   Q/K/V、每个方法、张量变化
datasets/images.py    处理中   初始化、取样、增强、batch 格式
train.py              待复核   入口、训练步骤、验证、保存调用
utils/metrics.py      已完成   函数逐项复核；diff/AST 检查通过
```

上表只是记录格式示例。实际清单应来自当前项目；“已完成”必须有检查依据。先按依赖关系安排阅读，再逐文件完成；不同时重写整个项目。任务较大时分批推进、保留进度，上下文压缩后接续，不因篇幅或工具方式自行降档、漏文件。

## 2. 读懂以后再写

1. 完整阅读当前目标文件，列出所有类、方法、函数、嵌套函数和模块级执行步骤，再看必要调用关系、配置和数据格式。有 CodeGraph 时优先用它查看结构与调用关系；返回内容有缺口时补读缺失部分，不能把截断片段当作整个文件，否则使用当前可用的搜索和阅读工具。
2. 沿着“输入 → 中间张量 → 输出”检查计算。例如，先确认 `x` 是图像还是 token，再解释 `flatten` 合并了哪些维度。
3. 只写能确认的形状。动态维度用 `B`、`N` 等符号；依赖配置时写明条件，不凭空写成固定数字。
4. 只有核对过论文或实现来源，才写“对应论文中的某个公式”。推测就注明是推测，不把它说成作者的设计意图。
5. 发现 bug 时说明位置和依据，修复单独处理，不在加注释时顺便改算法。

## 3. 怎么写注释

- 重要文件说明它做什么、接收和返回什么、在哪一步被调用。已有准确且达到所选档位的说明保留；准确但过于简略的说明要扩充，不把“已有一句注释”当作已经完成。
- 核心类和函数可用 docstring（定义下方的三引号说明）解释用途、参数、返回值和限制，不整段删除原有英文技术文档。
- 多解释“为什么”，少复述代码。例如：

  ```python
  # 信息太少：把 labels 转成 long。
  # 更有用：此处使用类别索引标签，CrossEntropyLoss 要求标签为整数类型。
  labels = labels.long()
  ```

- 在 `forward`、`reshape/view`、`permute/transpose`、`flatten`、池化、Q/K/V、拼接和特征输出处标出关键 Shape。
- `softmax` 说明沿哪个轴归一化；广播说明哪一项被扩展；`detach/no_grad` 说明哪些计算不记录梯度。只解释实际发生的事，不因函数名叫 attention 就套用某个算法。

常用形状符号如下；首次出现时说明，不要求每处重复：

| 符号 | 含义 | 例子 |
|---|---|---|
| B | 一批样本数 | B=2 表示一次处理 2 个样本 |
| C、H、W | 通道数、图像高、图像宽 | 图像 `(B, C, H, W)` |
| N、D | token 数、每个 token 的特征维度 | token 序列 `(B, N, D)` |
| A、Dh | 注意力头数、每个头的特征维度 | 多头张量 `(B, A, N, Dh)`；`D = A * Dh` |
| K | 类别数 | 分类输出 `(B, K)` |

例如，只知道输入是 `(B, N, D)` 时这样标注，不猜 `N=196`：

```python
x = x.transpose(1, 2)  # (B, N, D) -> (B, D, N)
```

只加注释时必须保留原代码的计算和接口：

- 不改函数签名、默认值、返回结构、运算顺序、配置、路径或实验安排；不添加打印、assert、类型提示或重命名。
- 保留文件头、编码声明、许可证、`from __future__` 导入位置，以及 `type: ignore`、`noqa` 等工具指令。模块 docstring 应放在 future import 之前，并保留已有文件头。
- docstring 能被程序读取。若代码通过 `__doc__` 注册对象或解析信息，先检查其用途，必要时只加 `#` 注释。

### 3.1 档位决定讲多细，编辑模式决定怎样落实

| 注释档位 | 默认编辑模式 | 做法 |
|---|---|---|
| 简洁 | `patch` | 在易误读处补充必要说明，保留已满足要求的注释 |
| 标准 | `rewrite` | 逐文件形成完整注释版本，说明各接口的用途、输入输出和主要步骤 |
| 教学 | `rewrite` | 逐文件形成完整教学版本，展开算法、数据流、张量变换与梯度影响 |
| 标准/教学 + 文件过大 | 分段实施 `rewrite` | 按完整函数、类或代码段完成，最后复核整个文件 |

`patch` 是通过 `apply_patch`、字符串替换等修改局部；`rewrite` 是从当前源码出发，按文件顺序生成完整注释版本，**不是重新实现算法**。标准档采用 rewrite 也仍按标准密度写，不自动变成教学档。

补丁工具能插入大量注释，整文件写入也可能写得很少；覆盖范围取决于规划和复核。只支持补丁时，仍按完整文件计划逐段落实，不能因工具叫 `apply_patch` 就只补几个位置。用户指定教学档 + patch 时同样满足教学覆盖要求；指定简洁档 + rewrite 时也不增加无关解释。

### 3.2 分开“生成注释”和“写回文件”

1. **记录当前版本**：以磁盘上当前内容为准，包含尚未提交的改动，保存原始内容或摘要。记录编码、换行、文件头和需保留的工具注释，不从 Git 历史版本重新生成文件。
2. **生成完整注释版本**：逐项处理文件清单中的定义和执行步骤。标准档解释用途、参数、返回值和主要原因；教学档进一步解释算法步骤、Shape、轴、广播、训练/评估差异及梯度边界。缺少算法或维度依据时标明条件，不编造。
3. **先暂存、再检查**：rewrite 优先写到与目标文件相邻或指定临时目录中的候选文件，保证只增加或扩充注释/docstring；不重新排版计算代码、补依赖、改类型或重构。候选文件只是中间产物，完成后按任务范围清理，不留给自动扫描代码的工具误用。
4. **验证后写回**：按第 5 节比较原始内容与候选版本。写回前再检查源文件是否仍与记录一致；发生并发编辑时保留对方改动，重新阅读并合并注释，不直接覆盖旧快照。保持原文件编码、换行和权限。
5. **完整复核**：写回后再看最终 diff，按清单检查整个文件。用补丁直接修改时也保留原始快照，执行同样检查；不得把“补丁成功”或“候选文件生成”当作完成。

一个函数或类连同说明无法可靠一次处理、或输出可能截断时，拆成多个完整定义/代码段。每段保留未处理区域，记录段间的输入输出，最终合并后做整文件语法与 AST 比较；不截断函数，不用 `...`、“其余代码同上”等代替真实源码。

### 3.3 教学档的覆盖检查

对每个文件逐项复核，不用新增注释行数、diff 大小或机械逐行复述代替质量判断：

| 检查对象 | 教学档需要回答的问题 |
|---|---|
| 文件和模块级执行 | 文件负责什么？由谁调用？初始化和入口按什么顺序运行？ |
| 每个类、方法和函数 | 做什么？输入输出是什么？谁调用它？哪些条件、状态或副作用需要注意？ |
| 关键算法和分支 | 每一步算什么、为什么这样算？不同分支分别在什么条件下执行？ |
| 张量操作 | 形状如何变化？每个轴代表什么？reshape、拼接、广播、softmax 的对象是什么？ |
| 训练和数据流程 | 如何取样、划分、算损失、回传梯度、更新参数、评估或保存？ |
| 小工具和包装函数 | 在流程中承担什么职责？若只有简单转发，也说明其连接关系，不略过整个定义 |

只检查实际存在的对象，不给没有张量的工具函数硬加 Shape，也不对已有足够详细的说明再重复一份。存在无法确认的信息时，写明条件或待核实并记录状态。
**只有已复核目标文件全部定义、关键算法和张量操作，且没有待注释、待验证或未知部分，才把该文件标为完成。** 无关的第三方实现可按边界说明，不替代当前文件自身的解释。全项目任务只有清单中所有纳入文件完成，才宣称整个项目完成；有阻碍就列出未完成项，并继续能独立处理的部分。

## 4. 三种详细程度的同一段代码

下面三段使用**完全相同的计算**，只改变注释。每段都是独立示例，选一段使用即可，不需要复制三份函数到项目。

示例计算简化的多头自注意力：`q/k/v` 都是 `(B, A, N, Dh)`，已由上游代码生成；这里不展示生成 Q/K/V 的线性层、mask、dropout 和最后的输出投影。实际项目仍保留原有步骤。

例如 `B=2, A=4, N=8, Dh=16`，输出为 `(2, 8, 64)`，因为 `D = 4 * 16 = 64`。

### 4.1 简洁：只标用途和关键点

```python
def attention_context(q, k, v):
    """合并各注意力头的输出，返回 (B, N, A * Dh)。"""
    batch_size, num_heads, num_tokens, head_dim = q.shape
    scale = head_dim ** -0.5
    scores = (q @ k.transpose(-2, -1)) * scale
    weights = scores.softmax(dim=-1)  # 沿 key 位置归一化。
    context = weights @ v
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )  # (B, A, N, Dh) -> (B, N, A * Dh)
```

### 4.2 标准：说明输入输出和主要步骤

```python
def attention_context(q, k, v):
    """计算各 token 的注意力特征，并合并多个头。

    参数：
        q/k/v：形状均为 (B, A, N, Dh) 的 query、key、value 张量。
            本示例要求序列长度相同，Dh > 0，dtype 和 device 兼容。
    返回：
        (B, N, D) 的特征，其中 D = A * Dh。
    """
    batch_size, num_heads, num_tokens, head_dim = q.shape
    scale = head_dim ** -0.5

    # 计算 query 与 key 的相似度，并用 1/sqrt(Dh) 缩放。
    scores = (q @ k.transpose(-2, -1)) * scale  # (B, A, N, N)
    weights = scores.softmax(dim=-1)  # 每个 query 对所有 key 的权重和为 1。
    context = weights @ v  # 按权重汇总 value，得到 (B, A, N, Dh)。

    # 把 token 放到头数之前，再合并 A 与 Dh，恢复每个 token 的完整特征。
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )  # (B, A, N, Dh) -> (B, N, A, Dh) -> (B, N, D)
```

### 4.3 教学：展开每一步为什么这样做

```python
def attention_context(q, k, v):
    """让每个 token 根据与其他 token 的相关程度，汇总它们的 value 特征。

    参数：
        q/k/v：形状均为 (B, A, N, Dh)，要求序列长度相同，Dh > 0，
            dtype 和 device 兼容。
        q（query）用于发起匹配，k（key）用于计算匹配分数，
        v（value）提供最后被加权汇总的特征。
        B 是样本数，A 是头数，N 是 token 数，Dh 是每个头的特征维度。
    返回：
        (B, N, D) 的特征，其中 D = A * Dh。
    """
    batch_size, num_heads, num_tokens, head_dim = q.shape

    # 1. Dh 越大，点积的数值幅度可能越大。
    # 用 1/sqrt(Dh) 缩放，缓和 softmax 权重过于集中的问题。
    scale = head_dim ** -0.5

    # 2. transpose(-2, -1) 交换 k 的 token 维和特征维。
    # (B, A, N, Dh) @ (B, A, Dh, N) -> (B, A, N, N)
    # 最后两个 N 分别是 query 位置和 key 位置。
    scores = (q @ k.transpose(-2, -1)) * scale

    # 3. 最后一维对应所有 key；每个 query 在这一维上的权重和为 1。
    # dim=-1 指最后一维，不是 batch 维或 head 维。
    weights = scores.softmax(dim=-1)

    # 4. 按权重对 value 做加权求和。
    # (B, A, N, N) @ (B, A, N, Dh) -> (B, A, N, Dh)
    # 每个 query 位置得到一个汇总后的 Dh 维特征。
    context = weights @ v

    # 5. 先变成 (B, N, A, Dh)，让同一 token 的各头特征排在一起，
    # 再合并成 (B, N, A * Dh)。直接合并原张量会混淆头与 token 的顺序。
    # transpose 后内存可能不连续；reshape 必要时会复制，而 view 要求布局兼容。
    # 这里没有 detach 或 no_grad：若输入需要梯度，梯度会沿这些运算传回上游。
    return context.transpose(1, 2).reshape(
        batch_size, num_tokens, num_heads * head_dim,
    )
```

选择档位后，按这个密度处理实际代码；示例不是要求把已有 Attention 改写成上述函数。

## 5. 检查和交付

- 看修改前后的 diff，确认只变了注释或 docstring，没有误改导入、计算、接口或配置。
- 可比较注释前后的语法树（AST）。只忽略模块、类、函数开头真正的 docstring，不忽略其他字符串，因为字符串也可能参与计算。
- AST 相同只能说明代码结构没变；仍需检查读取 `__doc__` 的代码，以及供工具使用的注释。
- 使用已有相关检查，不为注释启动完整训练。缺依赖时先做语法检查，并明确说明没有运行代码。
- 核对每处 Shape、轴和条件，无法确认的内容写明依赖或待核实。
- 交付时说明档位与 patch/rewrite 模式，列出已完成、待复核、受阻和排除的文件及原因，给出逐文件覆盖与验证结果。不能只报“添加若干行注释”，或只改少数文件就称整个项目完成。只要求注释时不额外生成新架构或图表；项目构建任务则回主入口完成剩余交付。

### AST 比较的短示例

下面只演示检查计算结构，`before` 和 `after` 是已经按原编码读取的原始内容、候选内容。同一 Python 解释器解析两份代码，先确认语法可以编译，再只移除模块、类、函数开头真正的 docstring：

```python
import ast


class IgnoreDocstrings(ast.NodeTransformer):
    def strip_docstring(self, node):
        self.generic_visit(node)
        if ast.get_docstring(node, clean=False) is not None:
            node.body = node.body[1:]
        return node

    visit_Module = strip_docstring
    visit_ClassDef = strip_docstring
    visit_FunctionDef = strip_docstring
    visit_AsyncFunctionDef = strip_docstring


def executable_ast(source):
    compile(source, "<annotation-check>", "exec")
    tree = IgnoreDocstrings().visit(ast.parse(source))
    return ast.dump(tree, include_attributes=False)


if executable_ast(before) != executable_ast(after):
    raise ValueError("注释候选版本改变了代码结构，停止写回并检查差异。")
```

不能过滤全部字符串：`message = "error"` 或 `return "train"` 仍是程序数据。本示例也不检查 `noqa`、`type: ignore` 等工具指令与文件头，需通过 diff 单独核对；读取 docstring、源码行号或源文本的代码也可能受影响，按实际用途检查。AST 一致不代表教学覆盖已经充分，两项都要通过。
